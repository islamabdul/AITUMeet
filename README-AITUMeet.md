# AITUMeet

Социальная сеть студентов Astana IT University. Интерфейс написан на HTML, CSS и JavaScript. Сервер — TypeScript/Vinext, база данных — Cloudflare D1 (SQLite), изображения — Cloudflare R2. Для работы аккаунтов нужен сервер: одного HTML-файла недостаточно для общей базы пользователей.

## Что работает

- Регистрация только по адресу `123456@astanait.edu.kz`: ровно шесть цифр; они становятся неизменяемым ID. Ведущие нули сохраняются. Дубли запрещены.
- Вход и выход, недельная сессия в HttpOnly cookie, смена пароля с завершением всех сессий.
- Профиль: имя, специальность, курс, биография, интересы, аватар, обложка, число публикаций и подписок.
- Публикации с фото, темы, подписки, лайки, закладки, комментарии, удаление собственных публикаций, ссылки на отдельные публикации.
- Поиск студентов по имени, ID и специальности, личные сообщения, уведомления о комментариях и непрочитанных сообщениях.
- Адаптивный интерфейс, мобильное меню, клавиатурная навигация, диалоги и обработка ошибок.

Гостевая лента и профили помечены как примеры. Они не записываются в базу. После регистрации показываются реальные данные. Проверочные аккаунты создавались только в локальной базе и не включены в архив или опубликованную базу.

## Ограничение студенческой почты

Проверяется **формат** адреса. Подтверждение **владения** почтой через письмо не подключено. Нельзя считать зарегистрированного пользователя проверенным студентом. Перед открытием сети университету нужно подключить отправку одноразовых кодов через почтовый сервис и допускать к регистрации только после проверки кода. Восстановление забытого пароля также требует почтового сервиса.

## Быстрый запуск без установки библиотек

1. Установите Node.js версии 22.13 или новее.
2. Распакуйте архив в отдельную папку.
3. Дважды нажмите `START.cmd` (Windows) либо выполните `node local-server.mjs` в папке проекта.
4. Откройте `http://127.0.0.1:3000`.

Локальный сервер использует встроенную SQLite, сам создаёт таблицы и хранит аккаунты и фото в папке `data/`. Установка npm-пакетов для этого способа **не нужна**. Оставьте окно сервера открытым, пока используете сайт. Сервер слушает только этот компьютер; это ещё не публикация в интернете. Перед обновлениями сохраняйте резервную копию папки `data/`.

В `local/api.mjs` находится готовая JavaScript-версия серверного кода. Для разработчика: после изменения `app/api/[...path]/route.ts` выполните `node scripts/build-local.mjs` (потребуются npm-зависимости), чтобы обновить локальную версию.

## Запуск окружения для разработки и облачной версии

Установите Node.js 22.13+ с npm. В папке проекта выполните:

```text
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_unique_sleeper.sql
npm run dev
```

Откройте адрес, который напечатает сервер (обычно `http://localhost:5173`). Миграцию следует применять один раз к новой локальной базе. Не запускайте её повторно после создания таблиц. Если npm блокирует сценарии установки, изучите его вывод и разрешайте только необходимые проверенные зависимости.

Для запуска уже собранной версии: `npm start`. Локальная база хранится в `.wrangler/state` и общая для dev/start. Удаление этой папки удаляет локальные аккаунты и файлы.

`public/index.html` можно открыть как визуальный макет, но для регистрации и остальных операций нужен сервер. Из корня проекта `/` направляет на `/index.html`.

## Файлы

- `public/index.html` — HTML-страница.
- `public/styles.css` — оформление и мобильная адаптация.
- `public/app.js` — интерфейс и запросы к серверу.
- `public/assets/aitumeet.png` — предоставленный логотип.
- `app/api/[...path]/route.ts` — серверные проверки и операции.
- `db/schema.ts`, `drizzle/` — структура и миграция базы.
- `tests/api-smoke.mjs` — интеграционные проверки только на локальном сервере.
- `.openai/hosting.json` — настройки Sites и привязки DB/BUCKET.

## Защита данных

Пароли хешируются PBKDF2-SHA256 с индивидуальной случайной солью; открытые пароли не сохраняются. Сессии случайные, их токены в базе также хешируются. На HTTPS cookie имеет Secure, HttpOnly и SameSite=Lax. Запись требует специального заголовка и проверки Origin. Сервер проверяет владельца каждой операции, ограничивает число запросов и размер файлов, использует параметры SQL. Пользовательский текст экранируется перед отображением.

Личные сообщения доступны только участникам переписки. Сквозное шифрование не реализовано. Администратор базы технически имеет доступ к данным. Все зарегистрированные пользователи могут просматривать профили и опубликованные изображения. Университетская почта показывается только владельцу профиля.

## Проверка

При запущенном локальном сервере:

```text
node tests/api-smoke.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

Проверки API создают отдельные тестовые аккаунты в локальной базе. Скрипт отказывается работать с удалённым адресом. Проверены вход, сохранение ID с ведущим нулём, запрет неверных адресов и дублей, профиль, публикации, лайки, комментарии, подписки, закладки, переписка, файлы, CSRF, смена пароля и запрет удаления чужой публикации.

## Публикация

Проект в Sites зарегистрирован с приватным доступом владельца, но **не опубликован**: автоматическая проверка разрешений заблокировала интерактивный шаг синхронизации исходников. Это не открытый студенческий сервис. Изменение аудитории — отдельное действие. Для нового независимого развёртывания создайте собственный проект, D1 и R2; не используйте идентификатор проекта владельца как свой.

Перед публичным запуском также нужны проверка почты, восстановление пароля, модерация/жалобы, резервное копирование и правила работы с персональными данными. Это явно обозначенные следующие этапы, а не имитация уже работающих функций.

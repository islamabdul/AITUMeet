# AITUMeet — Supabase

Социальная сеть студентов Astana IT University на HTML, CSS и JavaScript. Аккаунты, профили, публикации, сообщения и изображения хранятся в Supabase. Локальной базы данных и демонстрационных пользователей нет.

## Подключение Supabase

1. Создайте новый проект Supabase.
2. В SQL Editor выполните весь файл `supabase/schema.sql` **один раз в новом проекте**. Он создаёт таблицы, правила доступа, представления и приватное хранилище `aitu-media`. Если уже установлена предыдущая схема AITUMeet v0.2, выполните только `supabase/migrations/20261022_academic_profiles.sql`: она добавляет справочник и поля учёбы, сохраняя аккаунты и публикации. Полный `schema.sql` повторно поверх существующих таблиц не запускайте.
3. В Authentication → Providers → Email включите регистрацию по email и **Confirm email**. Правила доступа проверяют отметку подтверждения Supabase. Не отключайте этот переключатель: при отключении Supabase автоматически считает почту подтверждённой без проверки владения.
4. В Authentication → URL Configuration задайте Site URL вашего сайта. В Redirect URLs добавьте точный адрес страницы подтверждения, например `https://ваш-домен/index.html`. Для локальной проверки добавьте `http://127.0.0.1:3000/index.html`.
5. Настройте отправку писем в Authentication → SMTP. Для писем настоящим студентам нужен собственный SMTP: встроенная отправка Supabase имеет ограничения получателей и частоты. Проверьте доставку письма на университетский адрес.
6. Откройте `public/config.js` и вставьте Project URL и **publishable key** (либо старый публичный `anon` key):

```js
window.AITU_CONFIG = Object.freeze({
  supabaseUrl: 'https://ВАШ-ПРОЕКТ.supabase.co',
  supabasePublishableKey: 'ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ',
  storageBucket: 'aitu-media'
});
```

Публичный ключ предназначен для браузера; данные защищаются правилами RLS. **Никогда не вставляйте `service_role`, `sb_secret_…`, пароль базы или SMTP-пароль в файлы сайта.** Эти ключи обходят ограничения доступа. Клиент дополнительно отклоняет известные форматы привилегированных ключей.

До подключения Supabase можно проверить внешний вид, темы и языки. Формы входа и регистрации показывают сообщение о необходимом подключении; имитации успешной регистрации нет. Доставка писем и реальная работа с облаком проверяются после заполнения конфигурации.

## Запуск

Нужен Node.js 22.13 или новее. В Windows запустите `START.cmd`, либо выполните в папке проекта:

```text
node server.mjs
```

Откройте `http://127.0.0.1:3000`. Сервер только раздаёт файлы из `public/` и не создаёт локальные аккаунты или базу. Установка библиотек для запуска не нужна. `local-server.mjs` сохранён как совместимый запуск того же статического сервера.

Для обычного статического хостинга загрузите содержимое `public/`. Или выполните `npm run build` (установка пакетов не требуется): результат будет в `dist/`. После изменения `public/config.js` повторите сборку. Открывать сайт нужно через HTTP/HTTPS, а не двойным нажатием на HTML-файл.

В Docker/Railway можно задать `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` как переменные окружения вместо редактирования `public/config.js`. Используйте исключительно публичный ключ. `.env.example` — шаблон для Docker Compose; обычный `node server.mjs` сам `.env` не загружает. Запуск Docker Compose: `docker compose up --build`. Для сервера задайте `HOST=0.0.0.0`, если он должен принимать внешние соединения.

## Что изменено

- Демонстрационные люди, боты и публикации удалены. Пустые разделы заполняются только реальными участниками.
- Сохранена тёмная тема; добавлена светлая в белых и голубых тонах. Переключатель — в верхней панели.
- Русский, английский и казахский интерфейс, включая формы и сообщения об ошибках. Выбранные язык и тема сохраняются после перезагрузки.
- При регистрации пользователь выбирает уникальный `@username`: 3–24 латинские буквы, цифры или `_`, первая — буква. Тег можно изменить в профиле.
- Регистрация допускает только `123456@astanait.edu.kz`: ровно шесть цифр. Баркод сохраняется текстом, поэтому ведущие нули не теряются.
- Баркод находится исключительно в закрытой схеме `aitu_private`, без доступа из публичного API. В профиле, поиске, ссылках и сообщениях используется `@username`. Публичные профили не содержат ни студенческой почты, ни баркода. Служебные UUID Supabase нужны для связей данных и не являются студенческим баркодом.
- Вход и подтверждение почты через Supabase Auth; пароль меняется с проверкой текущего пароля. После смены выполняется выход на всех устройствах средствами Supabase (ранее выданные access-токены действуют до своего срока истечения).
- Редактирование профиля, аватар и обложка; публикации, фото, лайки, комментарии, подписки, закладки, поиск по имени/тегу/программе/группе, сообщения и уведомления.

Почта после регистрации не меняется через приложение, чтобы привязка к студенческому аккаунту оставалась неизменной. Старые локальные аккаунты автоматически не переносятся. Данных пользователей в `localStorage` нет: только настройки интерфейса и сессия Supabase Auth, необходимая для сохранения входа.

## Школы, программы и группы — v0.3

При регистрации и редактировании профиля школа и образовательная программа выбираются из связанных списков. По умолчанию выбраны **Electronic Engineering**, **1 курс**, группа **EE-26xx**. Участник вводит только последние две цифры: `01` превращается в `EE-2601`. Для второго курса префикс — `EE-25`, для третьего — `EE-24`; смена программы меняет буквенное сокращение, сохраняя введённые цифры.

Справочник сверён 22.10.2026 с [официальной страницей бакалавриата AITU](https://astanait.edu.kz/ru/bachelor): 17 образовательных программ в шести профильных школах. Школа общеобразовательных дисциплин также показана, но недоступна для выбора, поскольку отдельных программ бакалавриата в этом списке у неё нет.

Уточнённые владельцем проекта сокращения: **Electronic Engineering — EE**, **Computer Science — IT**, **Digital Technologies in Nuclear Power Engineering — DNE**, **Digital Jurisprudence — DL**. Для остальных программ временно используются согласованные сокращения названий; это не официальный справочник кодов групп университета.

Расчёт закреплён за учебным годом **2026/2027**. При переходе к следующему учебному году нужно согласованно обновить `academicYear` в `public/academics.js` и формулу года в SQL-функции `aitu_private.normalize_study_profile`. Существующим профилям без номера группа не выдумывается: две цифры участник указывает при следующем сохранении профиля. Неизвестные старые названия специальностей сохраняются до выбора программы.

Для казахского интерфейса подключён локальный **Noto Sans** с расширенной кириллицей и начертаниями 400–800. Он покрывает казахские буквы Ә, Ғ, Қ, Ң, Ө, Ұ, Ү, Һ, І. Файлы шрифта и лицензия OFL находятся в `public/fonts/`; обращение к Google Fonts при открытии сайта не требуется.

## Доступ к данным

Правила RLS проверяют подтверждённый студенческий аккаунт и владельца операции на стороне Supabase. Пользователь редактирует свой профиль, удаляет свои публикации и видит только свои закладки. Личные сообщения читают только участники переписки; менять текст отправленного сообщения нельзя. Изображения доступны вошедшим участникам по временным подписанным ссылкам, размер — до 2 МБ, форматы PNG/JPEG/WebP. Администратор Supabase имеет доступ к данным; сквозного шифрования сообщений нет.

Это независимый студенческий проект, а не официальный сервис университета. Восстановление забытого пароля, жалобы и административная модерация пока не реализованы.

## Основные файлы

- `public/index.html` — HTML-страница.
- `public/styles.css` — обе темы и адаптивный дизайн.
- `public/app.js` — интерфейс и взаимодействия.
- `public/i18n.js` — три словаря перевода.
- `public/academics.js` — школы, программы и правила формирования группы.
- `public/fonts/` — локальный шрифт для казахского интерфейса и лицензия.
- `public/preferences.js` — язык и тема перед загрузкой страницы.
- `public/supabase-api.js` — запросы к Supabase Auth, Postgres и Storage.
- `public/config.js` — параметры вашего Supabase.
- `public/vendor/` — Supabase JS 2.118.0 и его лицензия; загрузка SDK с CDN не требуется.
- `supabase/schema.sql` — структура облачной базы и правила доступа для нового проекта.
- `supabase/migrations/20261022_academic_profiles.sql` — обновление существующей схемы v0.2.
- `server.mjs` — только раздача статических файлов.
- `scripts/build-static.mjs` — подготовка папки `dist/`.

## Проверки для разработки

```text
npm ci
npm test
npm run build
```

Тесты проверяют полноту переводов, настройки интерфейса, отсутствие демо-данных, защиту от секретного ключа и реальные SQL-правила: закрытый баркод, уникальный тег, владение публикациями, приватные сообщения, файлы и запреты для гостей/неподтверждённой почты. Дополнительно проверяются справочник программ, формирование групп, ведущие нули, запрет подмены программы/группы и сохранность данных при повторном применении миграции. Для SQL-тестов используется отдельный PostgreSQL-совместимый движок PGlite **только в памяти тестового процесса**. Он не участвует в работе сайта и не создаёт локальную базу приложения.

Эти проверки не заменяют проверку конкретного проекта Supabase, SMTP и регистрации через настоящее письмо после подключения.

Официальная документация: [Auth](https://supabase.com/docs/guides/auth/managing-user-data), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage](https://supabase.com/docs/guides/storage/security/access-control).

# AITUMeet — Supabase

## [Открыть сайт AITUMeet →](https://islamabdul.github.io/AITUMeet/)

Адрес сайта: **https://islamabdul.github.io/AITUMeet/**. Страница `github.com/islamabdul/AITUMeet` содержит исходные файлы и этот README.

Социальная сеть студентов Astana IT University на HTML, CSS и JavaScript. Аккаунты, профили, публикации, сообщения и изображения хранятся в Supabase. Локальной базы данных и демонстрационных пользователей нет.

## Подключение Supabase

1. Создайте проект Supabase, когда будете готовы подключить аккаунты и данные.
2. Для **нового проекта** выполните `supabase/schema.sql` один раз в SQL Editor. Для существующей схемы применяйте миграции по порядку: обновление академического справочника и optional email confirmation для старых версий, затем миграции `20261104…` для Outlook, поиска и модерации. Они сохраняют аккаунты и публикации. Полный `schema.sql` поверх существующих таблиц повторно не запускайте.
3. В Authentication → Providers → Email включите регистрацию по email и **выключите Confirm email**. Это настройка Supabase: одним изменением HTML/JavaScript её отключить нельзя. При выключенном переключателе регистрация сразу возвращает сессию, без письма и кода подтверждения. Если он остался включён, сайт сообщает, что регистрация ещё настраивается.
4. В Authentication → URL Configuration задайте Site URL: `https://islamabdul.github.io/AITUMeet/`. SMTP и ссылка подтверждения для текущего сценария не нужны.
5. Для Outlook AITU настройте Azure (Microsoft Entra): создайте Web App Registration только для каталога организации и добавьте callback `https://rnvhpymwydnledjutwir.supabase.co/auth/v1/callback`. В Supabase → Authentication → Sign In / Providers → Azure укажите Application (client) ID, client secret и Azure Tenant URL `https://login.microsoftonline.com/<tenant-id>`; Tenant ID предоставит администратор AITU. Добавьте `https://islamabdul.github.io/AITUMeet/` в Redirect URLs. OAuth запрашивает scope `email`. В манифесте Entra также рекомендуется включить optional claim `xms_edov`, чтобы Supabase мог проверить, подтверждён ли адрес.

Без регистрации Entra-приложения и его реквизитов в Supabase кнопка Outlook не сможет завершить вход. База принимает адреса формата `123456@astanait.edu.kz`; при первом входе Outlook приложение предложит заменить автоматически созданный тег профиля.

Для входа Google Workspace создайте OAuth client типа Web application в Google Cloud. В Authorized JavaScript origins добавьте `https://islamabdul.github.io`, а в Authorized redirect URIs — Supabase callback `https://rnvhpymwydnledjutwir.supabase.co/auth/v1/callback`. Затем включите Google в Supabase → Authentication → Sign In / Providers и укажите Client ID и Client Secret. Вход через Google доступен для аккаунта AITU с адресом `@astanait.edu.kz`; личный `@gmail.com` не пройдёт серверную проверку студенческого домена. [Инструкция Supabase для Google](https://supabase.com/docs/guides/auth/social-sign-in/auth-google).
5. Откройте `public/config.js` и вставьте Project URL и **publishable key** (либо старый публичный `anon` key):

```js
window.AITU_CONFIG = Object.freeze({
  supabaseUrl: 'https://ВАШ-ПРОЕКТ.supabase.co',
  supabasePublishableKey: 'ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ',
  storageBucket: 'aitu-media'
});
```

Публичный ключ предназначен для браузера; данные защищаются правилами RLS. **Никогда не вставляйте `service_role`, `sb_secret_…`, пароль базы или SMTP-пароль в файлы сайта.** Эти ключи обходят ограничения доступа. Клиент дополнительно отклоняет известные форматы привилегированных ключей.

До подключения Supabase можно проверить внешний вид, темы и языки. Формы входа и регистрации показывают сообщение о необходимом подключении; имитации успешной регистрации нет. Регистрацию и сохранение данных нужно проверить после настройки конкретного проекта. Без подтверждения проверяется формат студенческой почты, но не владение адресом.

## Запуск

Нужен Node.js 22.13 или новее. В Windows запустите `START.cmd`, либо выполните в папке проекта:

```text
node server.mjs
```

Откройте `http://127.0.0.1:3000`. Сервер только раздаёт файлы из `public/` и не создаёт локальные аккаунты или базу. Установка библиотек для запуска не нужна. `local-server.mjs` сохранён как совместимый запуск того же статического сервера.

Для GitHub Pages оставьте Settings → Pages → Source: **GitHub Actions**: workflow публикует `public/index.html` вместе со всеми ресурсами. Если вручную выбрать публикацию корня ветки, корневой `index.html` перенаправит в `public/`.

Для обычного статического хостинга загрузите содержимое `public/`. Или выполните `npm run build` (установка пакетов не требуется): результат будет в `dist/`. После изменения `public/config.js` повторите сборку. Открывать сайт нужно через HTTP/HTTPS, а не двойным нажатием на HTML-файл.

В Docker/Railway можно задать `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` как переменные окружения вместо редактирования `public/config.js`. Используйте исключительно публичный ключ. `.env.example` — шаблон для Docker Compose; обычный `node server.mjs` сам `.env` не загружает. Запуск Docker Compose: `docker compose up --build`. Для сервера задайте `HOST=0.0.0.0`, если он должен принимать внешние соединения.

## Что изменено

- Демонстрационные люди, боты и публикации удалены. Пустые разделы заполняются только реальными участниками.
- Сохранена тёмная тема; добавлена светлая в белых и голубых тонах. Переключатель — в верхней панели.
- Русский, английский и казахский интерфейс, включая формы и сообщения об ошибках. Выбранные язык и тема сохраняются после перезагрузки.
- При регистрации пользователь выбирает уникальный `@username`: 3–24 латинские буквы, цифры или `_`, первая — буква. Тег можно изменить в профиле.
- Регистрация допускает только `123456@astanait.edu.kz`: ровно шесть цифр. Баркод сохраняется текстом, поэтому ведущие нули не теряются.
- Баркод находится исключительно в закрытой схеме `aitu_private`, без доступа из публичного API. В профиле, поиске, ссылках и сообщениях используется `@username`. Публичные профили не содержат ни студенческой почты, ни баркода. Служебные UUID Supabase нужны для связей данных и не являются студенческим баркодом.
- Регистрация и вход по почте и паролю через Supabase Auth, без этапа подтверждения почты; вход через Microsoft Entra (Outlook AITU) после настройки OAuth-провайдера. Пароль меняется с проверкой текущего пароля.
- Редактирование профиля, аватар и обложка; публикации, фото, лайки, комментарии, подписки, закладки, поиск по словам публикаций и по имени/тегу/программе/группе, сообщения и уведомления.

Почта после регистрации не меняется через приложение, чтобы привязка к студенческому аккаунту оставалась неизменной. Старые локальные аккаунты автоматически не переносятся. Данных пользователей в `localStorage` нет: только настройки интерфейса и сессия Supabase Auth, необходимая для сохранения входа.

## Школы, программы и группы — v0.3

При регистрации и редактировании профиля школа и образовательная программа выбираются из связанных списков. По умолчанию выбраны **Electronic Engineering**, **1 курс**, группа **EE-26xx**. Участник вводит только последние две цифры: `01` превращается в `EE-2601`. Для второго курса префикс — `EE-25`, для третьего — `EE-24`; смена программы меняет буквенное сокращение, сохраняя введённые цифры.

Справочник сверён 22.10.2026 с [официальной страницей бакалавриата AITU](https://astanait.edu.kz/ru/bachelor): 17 образовательных программ в шести профильных школах. Школа общеобразовательных дисциплин также показана, но недоступна для выбора, поскольку отдельных программ бакалавриата в этом списке у неё нет.

Уточнённые владельцем проекта сокращения: **Electronic Engineering — EE**, **Computer Science — IT**, **Digital Technologies in Nuclear Power Engineering — DNE**, **Digital Jurisprudence — DL**. Для остальных программ временно используются согласованные сокращения названий; это не официальный справочник кодов групп университета.

Расчёт закреплён за учебным годом **2026/2027**. При переходе к следующему учебному году нужно согласованно обновить `academicYear` в `public/academics.js` и формулу года в SQL-функции `aitu_private.normalize_study_profile`. Существующим профилям без номера группа не выдумывается: две цифры участник указывает при следующем сохранении профиля. Неизвестные старые названия специальностей сохраняются до выбора программы.

Для казахского интерфейса подключён локальный **Noto Sans** с расширенной кириллицей и начертаниями 400–800. Он покрывает казахские буквы Ә, Ғ, Қ, Ң, Ө, Ұ, Ү, Һ, І. Файлы шрифта и лицензия OFL находятся в `public/fonts/`; обращение к Google Fonts при открытии сайта не требуется.

## Доступ к данным

Правила RLS проверяют вошедший студенческий аккаунт и владельца операции на стороне Supabase. Пользователь редактирует свой профиль, удаляет свои публикации и видит только свои закладки. Личные сообщения читают только участники переписки; менять текст отправленного сообщения нельзя. Изображения доступны вошедшим участникам по временным подписанным ссылкам, размер — до 2 МБ, форматы PNG/JPEG/WebP. Администратор Supabase имеет доступ к данным; сквозного шифрования сообщений нет.

Это независимый студенческий проект, а не официальный сервис университета. Доступны роли «Администрация» и «Модерация» с бейджами в профилях. Обе роли могут удалять публикации, выдавать предупреждения, блокировать аккаунты на 7 или 30 дней либо бессрочно, снимать блокировки и разбирать жалобы. Активная блокировка ограничивает доступ через RLS. Назначить роль из браузера нельзя.

Владелец базы назначает роль в Supabase SQL Editor по точной студенческой почте (аккаунт должен быть заранее создан):

```sql
insert into public.aitu_staff_roles(user_id, role)
select id, 'administration' from auth.users
where lower(email) = lower('123456@astanait.edu.kz')
on conflict (user_id) do update set role=excluded.role;
```

Замените адрес в SQL на почту сотрудника. Чтобы назначить модератора, вместо `administration` укажите `moderation`.

## Проверки для разработки

```text
npm ci
npm test
npm run build
```

Тесты проверяют полноту переводов, настройки интерфейса, отсутствие демо-данных, защиту от секретного ключа и реальные SQL-правила: закрытый баркод, уникальный тег, владение публикациями, приватные сообщения, файлы и запреты для гостей и аккаунтов без студенческого профиля. Дополнительно проверяются справочник программ, формирование групп, ведущие нули, запрет подмены программы/группы и сохранность данных при повторном применении миграции. Для SQL-тестов используется отдельный PostgreSQL-совместимый движок PGlite **только в памяти тестового процесса**. Он не участвует в работе сайта и не создаёт локальную базу приложения.

Дополнительно проверяются регистрация без письма и безопасная обработка отсутствующей сессии. Эти проверки не заменяют проверку регистрации и входа в конкретном проекте Supabase после подключения.

Официальная документация: [Auth](https://supabase.com/docs/guides/auth/managing-user-data), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage](https://supabase.com/docs/guides/storage/security/access-control).
